# 2. 논문·프로젝트/

## 목적과 역할
논문 작업이나 실행 중인 프로젝트를 관리하는 공간입니다. 완료 조건이 있는지 없는지로 나누지 않고, **논문/프로젝트 단위로 폴더 하나씩** 둡니다.

## 폴더 구조
```
2. 논문·프로젝트/
  [프로젝트명]/
    00. 개요.md      ← 목표, 상태, todo, 진행 메모
    refs/            ← 관련 논문 레퍼런스 정리 (논문 1편당 노트 1개)
    진행 요약/         ← Z: 드라이브 등 실제 작업 중인 다른 디렉터리를
                        요청 시점에 Claude가 요약해 스냅샷으로 남기는 곳
```

## 어떤 노트가 들어가는가
- `00. 개요.md`: 프로젝트 목표/상태/todo. 반드시 `type: project`, `status`, `updated` 필드를 포함해 Dashboard에서 집계되도록 합니다.
- `refs/`: 논문 레퍼런스 노트. 서지정보(저자/출처/연도) + 자신의 언어로 쓴 요약을 포함합니다. 원문을 그대로 복사하지 않습니다.
- `진행 요약/`: 사용자가 "정리해줘/요약해줘"라고 요청할 때만 생성되는 스냅샷 노트입니다. 매번 새 노트를 만들고(날짜별로 누적), 기존 노트를 덮어쓰지 않습니다. 파일명에 날짜를 포함합니다 (예: `2026-08-07 진행 요약.md`).

## 작업 방식과 규칙
- refs와 진행 요약은 성격이 다릅니다: refs는 **외부 논문**을 정리한 것이고, 진행 요약은 **사용자가 다른 디렉터리에서 실제로 만들고 있는 작업물**을 스냅샷한 것입니다. 섞지 않습니다.
- 프로젝트가 끝났다고 해서 별도 Archive로 옮기지 않습니다. `status: completed`로만 표시해두고 폴더는 그대로 둡니다 (필요하면 나중에 정리).
- 새로 파악한 논문(신규 PDF, 후보 목록 항목 등)에 대한 설명·요약 노트는 항상 `refs/`에 논문 1편당 노트 1개로 만듭니다. 프로젝트 폴더 루트나 다른 곳에 설명 노트를 흩어두지 않습니다.
- `1. 추가 ref.md` 같은 후보 논문 목록 파일에는 원문 요약을 직접 쓰지 않고, 해당 논문의 `refs/` 노트를 `[[노트 이름]]`으로 링크한 뒤 그 옆에 한 줄 요약만 남깁니다. 상세 내용은 링크된 refs 노트에서 관리합니다.
